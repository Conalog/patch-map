# Shared behavior evidence

The [conformance design](../docs/engineering/flutter-conformance-design.md)
defines equality. Existing API pages own meaning; this directory stores its
language-neutral test inputs and required coverage inventory.

- `manifest.json` lists required semantic behavior and executable case IDs. Empty
  case lists are pending work, never passing support declarations.
- `witnesses.json` resolves case IDs to shared fixture commands or exact focused
  test names, assertions and scope. It is a static index, not an execution report;
  adding a case cannot mark a requirement passed. `manifest.fixtures` contains
  only the fixtures consumed by the exact observation comparator.
- `public-api.json` inventories the actual TypeScript export graph, including
  inherited public members, options and union shapes. Review changes before
  regenerating it with `node verification/conformance/inventory.mjs --write`.
- `fixtures/` includes all-kind rendering, authored versus instance updates,
  history and editor traces. `expected` entries are authored assertions; the
  current npm output is diagnostic evidence, not an automatically accepted
  replacement for the specification.
- `schema/fixture.schema.json` defines the envelope. Dataset field semantics
  remain with the owning public contract and dataset admission implementation.

Quick verification:

```sh
node verification/conformance/inventory.mjs
node --test verification/conformance/tools.test.mjs
node verification/conformance/run-data.mjs
node verification/conformance/run-text.mjs
node verification/flutter/package.mjs
```

Serve the repository using Vite and open `/verification/conformance/web/` for
the real npm gallery and public command traces. `window.patchMapComparison`
provides `traces()`, `snapshot()` and `reset(id)` for browser automation.

Compare matching npm/Dart observation envelopes with
`node verification/conformance/compare.mjs npm.json dart.json`. A successful
comparison covers only those observations. Full qualification separately uses
`node verification/conformance/qualify.mjs evidence.json`: it requires every
semantic and public API witness, installed artifact identities and Android/iOS
rendering, input, lifecycle, assets, accessibility and capture evidence. Missing,
skipped, duplicate or stale evidence cannot produce qualification success.

Only fixtures, inventory and the static witness index are committed. Run outputs belong under
`.artifacts/flutter/`. Run `node verification/flutter/prepare-fixtures.mjs` after editing shared fixtures.
It generates the example-only `sharedFixtureJson` Dart map, so hot restart also
refreshes scene inputs. The package verifier checks exact generated content and
shipped asset identity; the package library never imports these fixture inputs.

`text/cases.json` and its reviewed `text/expected.json` cover the pinned semantic
text profile. The npm runner verifies the current implementation against that
baseline, and Dart focused tests compare the same fields. Changing a baseline
requires a contract review; the runner only writes diagnostic output under
`.artifacts/flutter/`, never updates expected values automatically. Unicode
property range copies are also verified against the pinned npm tables.

`fixtures/codecs.json` embeds genuine PNG, JPEG, WebP, GIF, SVG, AVIF, TTF,
CFF OTF, WOFF and WOFF2 payloads. The original quadrant image and block glyphs
are MIT test artwork generated by `verification/flutter/prepare-codecs.py`; each
payload records its exact MIME, size and SHA-256. Images are 16×16 and every font
contains `AB 012`. Font outlines are generated from scratch rather than copied
from another font. Generator versions are pinned in the script.

Consumers register `assets`, acquire every `requiredAssets` alias through the
public asset runtime/session, then render the scene with that runtime. Font
registration alone is not decode evidence. `acquireSharedFixtureAssets()` is
the npm consumer helper and destroys its session on failure or teardown; native
creation receives the same registrations and visible font/image bindings await
real codecs. Positive format support does not cover malformed input, policy
rejection or lifecycle races; their required manifest entries remain separate.
