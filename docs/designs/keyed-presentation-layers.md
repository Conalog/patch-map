# Design: Keyed transient presentation layers

## Problem Statement

PatchMap needs a public way for a host to change the current frame's paint from
external runtime state without mutating PATCH MAP v0.10 data. The first consumer
is PlantMap focus: selection, filters, related physical/wiring projections, and
external highlights form one active ID set; scoped items outside that set render
at alpha `0.32`.

This is not a `highlight` feature. The host owns the meaning and composition of
selection, filter, alarm, search, and related-object state. PatchMap owns only
stable target membership, renderer-only paint composition, frame publication,
and cleanup.

`selection.visual` is not the right owner because it paints persistent selection
bounds only. Ordinary `update()`/`updateBatch()` are not the right owner because
they express semantic or concrete base-value replacement, while this state has a
keyed, composable, renderer-only lifetime.

## What Makes This Cool

A host can retarget one active object within a 10,000-object scope without
building 9,999 complement records, losing authored alpha, or coordinating the
clear order of several last-writer-wins updates. The same small primitive works
for focus, search, time-range filtering, permission dimming, and future alarm
paint without teaching PatchMap those business concepts.

## Constraints

- Preserve PATCH MAP v0.10 input immutability, stable identities, deterministic
  interpretation, and atomic failure.
- Preserve the aggregate PixiJS renderer, root interaction authority, central
  scheduler, and explicit resource ownership. Do not add per-entity display
  objects, listeners, tickers, or closures.
- Keep host business state outside PatchMap. Keys are opaque and PatchMap never
  interprets `focus`, `alarm`, `selection`, or similar names.
- MVP is paint-only and alpha-only. Geometry, source, text/content, bar height,
  show/visibility, structure, hit identity, and arbitrary PATCH MAP attrs are
  not presentation-layer properties.
- WebGL remains the production baseline. WebGPU and Windows-native performance
  stay pending until measured on their actual targets.

## Premises

1. The primitive is a keyed runtime paint modifier, not a business highlight or
   a second mutation mode.
2. The public API should expose a separate `presentation` domain because its
   lifetime, composition, restoration, revision, and capture behavior differ
   from mutation.
3. Extensibility comes from keyed layer composition and stable membership, not
   from shipping speculative paint properties or a selector/rule language.
4. A layer is an atomic snapshot. It does not silently expand when later scene
   edits create new logical targets.
5. Same-key sparse retarget normalization and logical diff are
   `O(previousTargets + nextTargets)`; dense recomposition and upload are
   `O(changedDenseSlots × activeLayerCount)`. Initial set, multiplier change,
   and clear may be O(scope) because every effective alpha changes.

## External API Precedents

- Mapbox separates runtime `feature-state` from source data and consumes it from
  style expressions: https://docs.mapbox.com/mapbox-gl-js/guides/user-interactions/interactions/
- deck.gl performs large-set filtering and fading on the GPU rather than
  materializing a filtered data array on the CPU:
  https://deck.gl/docs/api-reference/extensions/data-filter-extension
- Cytoscape recommends application state plus stylesheet classes over direct
  per-element style bypasses: https://js.cytoscape.org/index.html
- OpenLayers supports a removable per-feature style override and uses a separate
  overlay layer in its highlight example:
  https://openlayers.org/en/latest/apidoc/module-ol_Feature-Feature.html

These precedents agree on separating base style from runtime visual state. None
provides PatchMap's required combination of keyed composition, explicit
matched/unmatched complement, revision-bound semantic targets, and dense diff
publication. PatchMap therefore should adopt the separation principle without
copying a feature-state or stylesheet engine.

## Approaches Considered

- `updateBatch` transient discriminator was rejected because it would hide a
  second command grammar and different history/revision semantics inside the
  semantic mutation API.
- `visualState` plus declarative paint rules was rejected because the first
  alpha use case does not justify a selector, precedence, rule evaluation, and
  versioning subsystem.
- Chosen: a keyed `presentation` domain. `appearance` sounds like authored base
  style, `effects` suggests Pixi filters, and `visualState` implies PatchMap owns
  host state semantics. `presentation` is correct only with the explicit public
  definition that layers modify the rendered base and never replace it.

## Recommended Approach

### Public API

```ts
export type PatchMapPresentationTargetsInput =
  | string
  | readonly string[]
  | PatchMapTarget
  | readonly PatchMapTarget[]
  | PatchMapTargetSet;

export interface PatchMapPresentationPaint {
  readonly alphaMultiplier: number;
}

export interface PatchMapPresentationLayer {
  readonly scope: PatchMapTargetSet;
  readonly targets: PatchMapPresentationTargetsInput;
  readonly matched?: PatchMapPresentationPaint;
  readonly unmatched?: PatchMapPresentationPaint;
}

export interface PatchMapPresentationSetResult {
  readonly changed: boolean;
  readonly revision: number;
  readonly scopeCount: number;
  readonly targetCount: number;
  readonly matchedCount: number;
  readonly unmatchedCount: number;
  readonly ignoredTargetCount: number;
}

export interface PatchMapPresentationApi {
  set(key: string, layer: PatchMapPresentationLayer): PatchMapPresentationSetResult;
  clear(key: string): boolean;
}

export interface PatchMapApi {
  // existing domains remain unchanged
  readonly presentation: PatchMapPresentationApi;
}
```

Public validation and normalization:

- `key` is a non-empty string. It is opaque; docs recommend namespaced keys such
  as `plant-map:focus`, but PatchMap imposes no business vocabulary.
- `scope` must be one current, same-instance `PatchMapTargetSet`. Stale and
  cross-instance sets fail before any state changes.
- `targets` reuses the existing public target grammar: a raw string is an
  element/instance ID, `{ id, componentId }` is a component address, and a
  current target set may contain either. There is no presentation-only target
  or selector grammar. Duplicate logical addresses are removed.
- Syntactically valid targets that do not exist or fall outside `scope` are
  ignored. `ignoredTargetCount` makes that behavior observable without forcing
  the host to filter a shared active set.
- At least one of `matched` or `unmatched` is required. An omitted branch is the
  identity multiplier `1`.
- `alphaMultiplier` must be finite and within `[0, 1]`. Zero is allowed and
  affects paint only; hit testing, selection, and semantic visibility do not
  change.
- Caller-owned inputs are never mutated or frozen. PatchMap validates them,
  creates detached normalized internal copies, freezes only those copies, and
  then commits. Unknown fields fail. Any failure preserves the previous
  same-key layer and the presentation revision.
- `set(key, layer)` atomically replaces that key. Equivalent normalized state is
  a no-op. An empty scope is valid and can replace an existing layer with an
  inert snapshot. `clear(key)` removes only that key and returns `false` when it
  did not exist.
- No `clearAll`, callbacks, priority, selector language, or generic style patch
  ships in MVP.

### Target and composition semantics

- A scope target set is captured as detached canonical logical addresses from
  the existing exhaustive public taxonomy: element addresses `{ id }` and
  component addresses `{ id, componentId }`. A `relations` element is one
  element address whose dense projection owns its relation segments; individual
  relation links do not become a new public target kind. The snapshot remains
  fixed across ordinary updates; newly
  created addresses are outside the layer until the host queries and sets a
  replacement scope. The caller's original `PatchMapTargetSet` still follows
  the existing public reuse contract and may become stale after a scene
  revision, so a later `set()` must receive a newly queried set when required.
- Deleting a captured address temporarily removes its dense projection. Undo or
  recreate with the same stable logical address inside the same dataset
  generation reactivates the modifier. A different ID never joins the snapshot,
  and successful `data.replace()` clears the layer before same-string IDs from a
  new dataset can reactivate it.
- Effective matched membership is `scope ∩ targets`. Effective unmatched
  membership is `scope - targets`.
- Logical element/component addresses expand through the canonical semantic-to-
  dense target projection. Rendering membership is normalized as
  `matchedDense = project(scope ∩ targets)` and
  `unmatchedDense = project(scope) - matchedDense`. This deduplicates overlapping
  element/component projections and makes matched win when both logical paths
  reach the same dense primitive.
- Alpha applies to every existing opacity-bearing dense primitive reached by
  that projection, including background geometry, bars/tracks, icon/image
  quads, text/label quads, and all relation segments owned by a scoped
  `relations` element. The canvas/global background and package-owned interaction overlays
  such as selection bounds, marquee, and transformer handles are not semantic
  targets and remain unchanged.
- For each dense slot, effective alpha is:

  `baseAlpha × product(all applicable layer branch alphaMultiplier values)`

- `baseAlpha` includes authored alpha and current concrete grid-instance base
  presentation. Presentation layers are applied after those base values, so
  later semantic or concrete-base updates remain visible through the multiplier.
- Multiplication is commutative, so MVP has no priority or ordering contract.
  A future non-commutative paint property requires a separate public design that
  defines precedence and tie-breaking before that property ships.

### Runtime ownership and data flow

```text
host-owned state union
        │
        ▼
presentation.set(key, { scope snapshot, targets, matched, unmatched })
        │  validate + resolve logical membership atomically
        ▼
keyed presentation authority
│  sparse logical symmetric difference + targeted bit flips
        ▼
semantic-to-dense projection
        │  recompute effective multiplier only for dirty slots
        ▼
stable presentation store + aggregate Mesh dirty ranges
        │
        ▼
central frame scheduler / capture
```

- Keep one stable renderer presentation view. Do not allocate a new full wrapper
  or rebuild aggregate batches for every same-key retarget.
- Store each layer's canonical logical membership in sparse sets and its dense
  scope/matched membership in packed bitsets. Keep one effective multiplier
  column and one dirty-slot accumulator for the composed result.
- A same-key replace that reuses an equivalent scope normalizes the next target
  set, compares previous and next sparse logical membership, and flips only the
  affected dense bitset positions. It does not scan the scope bitset. Total
  caller-side work is `O(previousTargets + nextTargets)` because the supplied
  memberships must be read; recomposition and GPU upload are
  `O(changedDenseSlots × activeLayerCount)`, independent of complement size.
- Recompute the multiplier product across applicable layers for each dirty slot
  rather than dividing out an old factor. This keeps `alphaMultiplier: 0`
  correct. No fixed key limit ships; retained membership memory is
  `O(layerCount × denseCapacity / 8)` plus sparse logical target sets, and dirty
  recomposition scales with active overlapping layer count.
- Initial set, clear, or a branch multiplier change may dirty the full affected
  scope. This is an explicit O(scope) path, not a disguised sparse claim.
- Every successful semantic or structural commit reprojects surviving active
  layer addresses before the changed scene is published. A deleted address has
  no dense contribution; recreation of the same address reactivates it in that
  same publication. Dense primitives created later by viewport text culling,
  concrete-instance materialization, or asset settlement read the already
  composed multiplier before their first visible frame. These projection and
  materialization changes do not advance presentation revision or logical
  counts because the stored layer snapshot did not change; the ordinary scene
  and frame publication revisions carry them.
- Overlapping layers multiply through the same effective column. Concrete
  instance presentation remains the base-value owner and publishes into the
  existing presentation store before multipliers are applied.

### Lifecycle, capture, revisions, and debug

| Operation or surface | Contract |
| --- | --- |
| `capture.png()` | Includes all active presentation layers and waits for a frame representing at least the presentation revision observed when capture starts. A later synchronous superseding set may be included; capture does not freeze an earlier layer snapshot. |
| `data.snapshot()` / `serialize()` | Excludes presentation state. |
| Semantic hash / scene revision | Unchanged by presentation set/replace/clear. |
| History undo/redo | Does not record or rewind presentation; surviving stable IDs keep their modifiers. |
| Ordinary update | Keeps layer snapshots and recomputes from the new base alpha. |
| Successful `data.replace()` | Clears every layer atomically with dataset publication. |
| Failed `data.replace()` | Preserves the old dataset and every active layer. |
| Remount | Starts with no presentation layers. |
| `destroy()` | Clears bitsets, multiplier columns, dirty state, and pending presentation work. |

- A capture interrupted by destroy rejects through the existing lifecycle error
  contract. Load/capture supersession continues to use the single existing
  capture and publication authorities.
- Add a domain-local monotonic presentation revision with these exact rules:

  | Transition | Revision result |
  | --- | --- |
  | Initial state | `0` |
  | New key or changed same-key set | Increment once |
  | Equivalent normalized set | No increment; return current revision |
  | Clear existing key | Increment once |
  | Clear missing key | No increment |
  | Successful `data.replace()` with one or more active layers | Clear all and increment once |
  | Successful `data.replace()` with no active layers | No increment |
  | Failed `data.replace()` | No increment |

  It is not part of semantic hash or scene revision.
- Extend `debug.snapshot()` with a genuinely bounded aggregate only:

  ```ts
  presentation: {
    revision: number;
    layerCount: number;
  }
  ```

- Debug output never exposes keys, dense IDs, bitsets, renderer objects, or
  copied membership arrays. Hosts already own their keys; per-call set results
  provide membership diagnostics without growing the global debug snapshot.

### Count and equivalence definitions

- `scopeCount` is the number of unique canonical logical addresses captured by
  the scope target set.
- `targetCount` is the number of unique syntactically valid requested logical
  addresses before scope intersection. It includes valid unknown and
  out-of-scope IDs; input duplicates count once.
- `matchedCount` is the number of unique scope logical addresses selected by
  those requested addresses. `unmatchedCount = scopeCount - matchedCount`.
- `ignoredTargetCount` is the number of unique requested addresses that select
  no logical address in scope. Counts are logical-address counts, never dense
  slot or visible-primitive counts.
- Stored-layer equivalence compares canonical scope logical addresses,
  effective matched logical addresses, and normalized branch paint. Different
  attempted unknown/out-of-scope IDs therefore may produce an equivalent no-op.
  The no-op result still reports counts for the current attempted input while
  returning the unchanged revision.
- Layer storage uses `Map<string, ...>` so opaque keys never become object
  properties or participate in prototype lookup.

### Performance gate

Add a dedicated public-path WebGL Chromium benchmark over 5,000 and 10,000
renderable targets. Use two warmups, seven measured trials, and thirty
alternating retargets per trial. Keep a 5,000-target 4x CPU-throttle run as
diagnostic; do not substitute it for actual Windows-native evidence.

Normative budgets:

- One-active to another-active sparse replace with the same captured scope:
  synchronous `set()` p95 at most
  `5ms` for 5k and `10ms` for 10k.
- Sparse one-to-one retarget dirties at most the two changed logical-membership
  expansions, independent of scope size. The measured synchronous call includes
  target normalization, sparse membership comparison, dense recomposition, and
  frame scheduling.
- Initial set, multiplier-only replace, and clear: synchronous p95 at most
  `25ms` for 5k and `50ms` for 10k. Initial set includes scope detachment,
  semantic-to-dense projection, bitset allocation, composition, and scheduling;
  replacing with a different scope is measured as another full set.
- Sparse action-to-visible p95 at most `50ms` for 5k and `100ms` for 10k;
  rAF-gap p95 at most `75ms` and `150ms` respectively.
- In each 10k trial, sparse synchronous replace is at least four times faster
  than a paired same-scope multiplier-only replace in that trial. The paired
  full operation keeps one matched target fixed and alternates `unmatched`
  between `0.32` and `0.31`, forcing recomposition over the complement. Compute
  the ratio as full-operation synchronous p95 divided by sparse-retarget
  synchronous p95, with both boundaries spanning public call entry through
  returned result and frame scheduling.
- Every `set()` commits exact synchronous state, counts, and revision before it
  returns. Central scheduling may coalesce intermediate frames, but the latest
  committed revision must never be dropped. Measure synchronous burst behavior
  with thirty alternating calls followed by final-state/capture validation;
  measure action-to-visible p95 separately by awaiting publication after each
  retarget, so no benchmark assumes every burst intermediate becomes visible.
- Record long-task count and every unfavorable frame result, but keep Chromium
  long-task count diagnostic because the current 10k aggregate frame baseline
  already reports residual long tasks.
- After clear/destroy 2+7 and ten ownership cycles, presentation resources and
  pending frame work are zero and retained heap shows no monotonic growth.
- A separate 10k stress profile keeps four overlapping alpha layers active while
  retargeting one key. Its synchronous sparse p95 must stay at most `20ms`, its
  action-to-visible p95 at most `100ms`, and its retained membership allocation
  must match the documented bitset-plus-sparse-set complexity. This proves the
  composition extension point without claiming arbitrary-layer constant cost.

## Why This Is Not PlantMap-Specific

- `scope`, `targets`, and two paint branches describe a generic partition, not
  selection or highlight semantics.
- Omitting `unmatched` gives a targeted-only modifier; omitting `matched` gives
  complement-only dimming.
- Opaque keys allow independent consumers to own lifetimes without PatchMap
  learning their meaning.
- The MVP deliberately omits filter predicates, alarm severity, search ranking,
  selection coupling, automatic related-object projection, and a style rule
  language.
- Acceptance examples must include both PlantMap focus and one neutral second
  use case such as search-result focus or time-range de-emphasis. Neither may
  require a new public field.

## Test Plan

- Public boundary: root export allowlist, packed ESM/CJS/types consumer, exact
  `PatchMapInstance` domain shape, and no internal policy/dense types exposed.
- Validation and atomicity: empty/invalid keys, extra fields, NaN/infinite/out-
  of-range multipliers, stale/cross-instance sets, malformed targets, same-key
  replace failure, duplicate targets, empty scope, and equivalent no-op set.
- Membership: raw unknown/out-of-scope IDs are ignored and counted; stale target
  sets reject; element, component, authored, concrete grid-instance, and
  `relations`-element targets expand deterministically; raw strings resolve only
  element IDs while `{ id, componentId }` resolves components; overlapping
  element/component projections dedupe with matched precedence; empty targets
  intentionally select the unmatched branch for the whole scope.
- Composition: authored alpha, concrete-instance base alpha, matched/unmatched
  identity defaults, overlapping layer multiplication, key-isolated clear,
  alpha zero with unchanged hit identity, and ordinary base updates.
- Lifecycle: delete, recreate-same-ID, create-new-ID, successful/failed replace,
  history undo/redo, culled-text/instance/asset late materialization, capture
  supersession/settlement, capture interrupted by destroy, debug boundedness,
  remount, destroy retry, pending-frame cleanup, and caller input
  immutability/internal detachment.
- Renderer: sparse logical symmetric difference and targeted bit flips,
  structural reprojection before scene publication, late-materialization
  inheritance, full-scope invalidation cases, aggregate Mesh dirty ranges, frame
  coalescing latest-state correctness, and no per-entity display
  objects/listeners/tickers/closures.
- Performance and memory: run the fixed 5k/10k single-layer and 10k four-layer
  protocols above and retain honest raw results with digest-bound evidence.

## Success Criteria

- PlantMap can replace its former dimming plugin with one host-composed
  `plant-map:focus` layer and no complement payload.
- A neutral second consumer maps its state to the same API without new fields or
  PatchMap-owned business vocabulary.
- Base alpha restores exactly after key clear and survives changes made while a
  layer is active.
- Multiple keys compose deterministically and clear independently.
- Dataset/history/hash remain unchanged while capture reflects the visible
  frame.
- The 5k/10k functional, performance, memory, package, and lifecycle gates pass
  without weakening the aggregate renderer contract.
